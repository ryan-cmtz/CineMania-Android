# Guía para el cuestionario oral — Revisión 4

La rúbrica indica que se eligen seis preguntas al azar. Practica responder con tus palabras y, cuando te pidan ubicar algo, menciona el archivo indicado. Las respuestas describen la implementación actual de CineMania.

1. **¿Qué es Android?** Es un sistema operativo y una plataforma de software para dispositivos móviles. Permite ejecutar aplicaciones y ofrece APIs para acceder a funciones del dispositivo.
2. **¿Qué es Jetpack Compose?** Es el toolkit declarativo de Android para construir interfaces nativas mediante funciones Kotlin anotadas con `@Composable`.
3. **¿Estás implementando un framework y cuál o cuáles usas en tu aplicación?** La aplicación usa Android Jetpack: Jetpack Compose para la interfaz, Navigation Compose para las dos rutas, Room para la base local y Lifecycle/`ViewModel` para el estado. Hilt se usa para inyección de dependencias.
4. **¿Qué librerías usas y dónde se declaran o implementan?** Las dependencias se declaran en `app/build.gradle.kts` y sus versiones principales se administran en `gradle/libs.versions.toml`. Las uso en el código: por ejemplo Compose en `PantallaUno.kt` y `PantallaDos.kt`, Room en `data/` y Hilt en los módulos y ViewModel.
5. **¿Por qué el patrón Singleton no puede generar más de una instancia?** Porque su objetivo es mantener una sola instancia compartida dentro del alcance que define. En CineMania Hilt marca `AppDatabase` como `@Singleton` en `DatabaseModule.kt`, para reutilizar una única base en la aplicación. El alcance Singleton no significa que todas las clases sean únicas.
6. **Explica UDF y dónde lo implementas.** UDF significa flujo unidireccional de datos: el estado de la pantalla va del ViewModel hacia Compose, y las acciones del usuario vuelven como eventos o llamadas al ViewModel. En `PantallaDos.kt` se observa el estado y se llaman funciones de `ProductoViewModel.kt`.
7. **Explica Observer y dónde lo implementas.** Observer permite que un observador reciba cambios de una fuente. Los DAO de Room consultan como `Flow`; los repositorios y `ProductoViewModel` exponen esos cambios y Compose vuelve a dibujar la lista cuando cambian los datos.
8. **Explica inyección de dependencias y dónde la implementas.** Es proporcionar a una clase las dependencias que necesita desde fuera, en vez de crearlas allí. `RepositoryModule.kt` enlaza interfaces con sus implementaciones; `DatabaseModule.kt` proporciona la base y los DAO; Hilt inyecta los repositorios en `ProductoViewModel`.
9. **Explica Repository y dónde lo implementas.** Repository separa las reglas que consume la aplicación de los detalles de almacenamiento. `ProductoRepository` define el contrato y `ProductoRepositoryImp` usa `ProductoDao`; `CatalogoRepository` y `CatalogoRepositoryImp` hacen lo mismo para géneros, usuarios y reseñas.
10. **Explica UDF y dónde lo implementas.** Es el mismo flujo unidireccional de la pregunta 6: `ProductoViewModel` expone los datos y la pantalla envía acciones de guardar o eliminar al ViewModel.
11. **¿Qué es una función `suspend` y dónde la implementas?** Es una función que puede suspender una coroutine mientras espera una operación sin bloquear el hilo. Las operaciones de escritura de los DAO, como `insertar`, `actualizar` y `eliminar`, son `suspend`; el ViewModel las ejecuta dentro de `viewModelScope`.
12. **¿Qué anotaciones se usan para implementar Room?** `@Entity` define una tabla; `@PrimaryKey` declara su clave; `@Dao` marca la interfaz de acceso; `@Query`, `@Insert`, `@Update` y `@Delete` describen consultas y operaciones; `@Database` reúne entidades y DAO. Están en `data/`.
13. **¿Qué es un ViewModel y cómo lo implementas?** Es un componente que prepara y conserva el estado de la interfaz durante cambios de configuración, como la rotación. `ProductoViewModel.kt` expone los flujos de las cuatro tablas y contiene las acciones CRUD y validaciones; Compose lo obtiene con `hiltViewModel()`.
14. **Explica SOLID y cómo lo implementas.** SOLID son cinco principios para organizar software: responsabilidad única, abierto/cerrado, sustitución de Liskov, segregación de interfaces e inversión de dependencias. En CineMania se aprecia la separación de responsabilidades entre pantalla, ViewModel, repositorio y DAO, y la inversión de dependencias mediante interfaces de repositorio. No afirmo que todas las clases demuestren por completo los cinco principios.
15. **¿Para qué sirve `@AndroidEntryPoint` y dónde la implementas?** Marca un componente Android para que Hilt pueda participar en la inyección de dependencias. Está en `MainActivity.kt`, el punto de entrada de la aplicación.
16. **¿Para qué sirven `NavHost` y `NavGraphBuilder`?** `NavHost` muestra el destino actual y contiene el grafo de navegación; `NavGraphBuilder` permite declarar destinos dentro de ese grafo. En `AppNavegacion.kt` se registran las rutas `Home` y `Detalle` con `composable`.
17. **¿Para qué sirven `@Dao` y `@Entity`?** `@Dao` permite que Room genere el acceso a datos para una interfaz; `@Entity` define una tabla a partir de una clase. Por ejemplo, `ProductoDao.kt` y `ProductoEntity.kt`.
18. **¿Qué es una función de extensión y cómo la implementas?** Añade una función a un tipo sin modificar su declaración. En `data/mapper/ProductoMapper.kt`, `toDomain()` y `toEntity()` convierten entre `ProductoEntity` y `Producto`.
19. **¿Cuál es el punto de entrada de una aplicación Android?** Android inicia un componente declarado en el manifiesto. En este proyecto, `MainActivity` tiene el filtro `MAIN` y la categoría `LAUNCHER` en `AndroidManifest.xml`.
20. **¿Cómo se declara una función en Kotlin?** Se usa `fun nombre(parametros): Tipo { ... }`. Una función suspend lleva `suspend`, por ejemplo `suspend fun insertar(...)`; una función que declara interfaz Compose lleva `@Composable` antes de `fun`.
21. **¿Para qué sirve `@HiltAndroidApp` y dónde se implementa?** Inicializa el contenedor de dependencias de Hilt a nivel de aplicación. CineMania la declara en `CineManiaApp.kt`, que extiende `Application`.
22. **¿Cuál es la diferencia entre `@Preview` y `@Composable`?** `@Composable` identifica una función que construye UI Compose. `@Preview` permite mostrar una vista previa de una función composable en Android Studio; no reemplaza a `@Composable`.
23. **¿Cómo declaramos una interfaz de usuario en Jetpack Compose?** Con funciones `@Composable` que describen la interfaz a partir de estado y componentes como `Scaffold`, `Column`, `Text` y `Button`. En CineMania, `PrimeraPantalla` y `PantallaDos` son ejemplos.
24. **¿Qué lenguaje de programación ocupas?** Kotlin.
25. **¿Cuál es la diferencia entre `stringResource()` y `painterResource()` y dónde las implementas?** `stringResource()` obtiene texto de `res/values/strings.xml`; `painterResource()` carga un recurso gráfico para dibujarlo. `PantallaUno.kt` usa ambos para textos y el logo.
26. **¿Dónde puedes ver la versión de la API de Android usada para generar el proyecto?** En `app/build.gradle.kts`: `compileSdk` indica la API usada al compilar, `targetSdk` la API objetivo y `minSdk` la versión mínima. El proyecto declara 37, 37 y 24, respectivamente.

## Demostración breve del CRUD

En la pantalla **Catálogo**, abre cada pestaña: Películas, Géneros, Usuarios y Reseñas. Agrega un registro, comprueba que aparece en la lista, usa **Editar** y guarda el cambio, y finalmente usa **Eliminar**. Room guarda esos datos localmente en `cinemania.db`. Para demostrar persistencia, navega fuera y vuelve al catálogo o reinicia la app y verifica que los registros continúan.
